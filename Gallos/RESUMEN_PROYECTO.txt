1. DESCRIPCIÓN GENERAL
----------------------
Sistema web front-end (sin backend ni BD) para registro y control de
apuestas en peleas de gallos. Corre 100% en memoria (sessionStorage).
Diseñado para señores de rancho — interfaz intuitiva, oscura, cobre/ámbar.

Tecnologías: HTML + CSS + JS vanilla, jsPDF (CDN), Google Fonts (Outfit,
JetBrains Mono). Sin frameworks ni librerías externas (solo jsPDF para
exportación PDF).

5. PELEAS — MODELO DE DATOS
----------------------------
Cada pelea:
  num: int            ← Número único
  estado: string      ← 'espera' | 'activa' | 'cerrada'
  apuestas: array     ← [{ id, jugadorId, nombre, bando, monto, resultado }]
  minimizada: bool    ← Colapsada en UI
  ganador: string?    ← 'verde' | 'rojo' | undefined

La apuesta tiene resultado: 'pendiente' | 'ganada' | 'perdida'.

6. SISTEMA DE APUESTAS (lógica financiera)
--------------------------------------------
- 2 equipos por pelea: Rojo y Verde
- Cada jugador apuesta por un equipo
- Cuando se declara ganador, el 90% del pozo del perdedor va al ganador
- calcFicha(j): calcula saldo = totalGanadas - (saldoAnt + totalPerdidas)
- totalGanadas = sum(montos * 0.9) de apuestas ganadas
- El saldo se muestra en fichas con signo (+$X.XX o −$X.XX)
- Modal de apuesta muestra alerta si el jugador tiene saldo negativo
  (la apuesta se permite igual, pero queda registrado quién autorizó)

EMPLEADO (control total):

12. CONFIRM MODAL — REEMPLAZO DE CONFIRM()
--------------------------------------------
.showConfirm() devuelve Promise.
Renderiza overlay + box con icono, mensaje HTML, botón Cancelar y
botón Aceptar (primary o danger).
Teclado: Escape=cancelar, Enter=aceptar.
Se crea una vez y se reusa (no se duplica en DOM).

13. TEORÍA DEL NEGOCIO
-----------------------
Cada pelea tiene 2 equipos (Rojo/Verde). Los jugadores apuestan por
un equipo. Al declarar ganador:
  - Apuestas del equipo perdedor → se marcan 'perdida'
  - Apuestas del equipo ganador → se marcan 'ganada', reciben 90% de
    su monto apostado (el 10% es la casa/comisión)
  - El pozo del perdedor se reparte proporcionalmente entre los ganadores
  - Fórmula: Si gana Rojo → cada Rojo gana (apuesta * 0.9)
             Si gana Verde → cada Verde gana (apuesta * 0.9)
  - En reparte se muestra: "Si gana Rojo → $(totalVerde * 0.9)"
                           "Si gana Verde → $(totalRojo * 0.9)"

14. RESPONSIVE
--------------
Desktop (>1024px): Sidebar visible (hover), layout completo.
Tablet (768-1023px): Toolbar padding reducido, sidebar colapsado.
Mobile (<768px):
  - Sidebar invisible, topbar compacto con hamburguesa
  - Bottom nav fijo con iconos
  - P-cols cambia de grid a column (Rojo arriba, Verde abajo)
  - Fichas: tabla pierde/gana cambia a vertical
  - Filtros: pf-row con overflow-x:auto, .ctrl-sep oculto
  - Botones de estado ocultan texto (solo icono)
  - Modal: ocupa casi full screen (padding 8px)

15. REGLAS DE NEGOCIO
----------------------
- No se permite cerrar pelea sin ganador (redirige a botones ganador)
- Pelea cerrada con ganador se puede reabrir → limpia resultados
- Eliminar pelea → limpia apuestas de jugadores y ajusta peleaActual
- Nueva persona en modal → se registra automáticamente como jugador
- Apuesta con saldo negativo → se permite pero deja registro de quién
  autorizó + alerta visible en confirmación
- Máximo 300 registros en bitácora
- logout → sessionStorage.removeItem + redirect a index.html
- Login checkea sessionStorage → auto-redirect si ya hay sesión
